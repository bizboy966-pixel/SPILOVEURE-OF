## Root cause
The sync is working correctly and the deploy is live. The DRC does not appear because **Biz-transPay's live catalog API (`/mobile-money/operators`) does not return the DRC in any direction** — there is no operator with country `CD`/`COD` and no mention of Congo/RDC/CDF anywhere in the raw response. The app can only persist countries that BTP actually serves; it is not dropping or mis-mapping a DRC entry (if it were, `CD`/`COD` would appear in `raw_sample` — it does not). This is an upstream catalog/account configuration matter, not a code or fetch bug.

## Suggested fix
- **User / third party (Biz-transPay):** Confirm with Biz-transPay whether the DRC is enabled for this account/integration. BTP's `serving_environment_configuration` (the `availability_source` in the response) currently exposes only BF, BJ, CI, CM, ML, NE, SN, TD, TG. If the DRC should be available, BTP must enable it on their side; once it appears in the API response, the existing sync will pick it up automatically. Also clarify with BTP which code they use for the DRC (`CD` vs `COD`) so any front-end country mapping matches once it is live.
- No code change is warranted based on current evidence — the sync faithfully stores whatever BTP returns. (Only if BTP returns the DRC under an unexpected code/shape would an E1 mapping fix be needed; cannot be confirmed until BTP returns it.)
