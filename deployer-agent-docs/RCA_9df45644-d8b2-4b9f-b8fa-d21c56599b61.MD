## Cause racine
Entre `pick_provider` (qui retourne correctement `biztranspay`, ready:true) et l'appel BTP `/payouts`, `dispatch_biztranspay_withdrawal` avorte à l'étape de résolution de l'opérateur : la valeur `withdrawal.operator = "Mixx By Yas"` (rebrand Yas/Togo) ne correspond à aucun `operator_code` biztranspay actif pour TG (`tmoney_tg`, `moov_tg`). L'abandon se fait sans persister `gateway_error`, d'où le retrait qui reste `pending` (puis rejeté à la main). Incohérence de nommage sur 3 niveaux :
1. libellé côté retrait/UI : `"Mixx By Yas"`
2. `operator_code` en base : `tmoney_tg` / `moov_tg` / `togocom_tg`
3. clés `biztranspay_countries.TG` : `flooz_tg`

## Fixes (côté user — je ne modifie rien)
1. **[Code]** Dans `biztranspay.py` (v27y) : normaliser/mapper le libellé opérateur `"Mixx By Yas"` (et les autres libellés UI Togo) vers un `operator_code` biztranspay actif (`tmoney_tg` ou `moov_tg`) dans la table `OPERATORS`/la résolution d'opérateur du dispatcher. Aligner aussi le dropdown opérateur TG du frontend et les clés de `app_settings.payment_gateway.biztranspay_countries.TG` sur les mêmes `operator_code` (supprimer `flooz_tg` orphelin).
2. **[Code]** Rendre l'échec observable : persister `gateway_error`/`gateway_error_code` (ex: `operator_not_supported`) sur le doc `withdrawals` quand la résolution d'opérateur échoue, au lieu de laisser le retrait silencieusement en `pending`.
3. **[User]** Vérifier/corriger le secret `BIZ_TRANSPAY_BASE_URL` (actuellement non-vide et non-canonique) dans Deployment Panel → Secrets : le vider OU le fixer exactement à `https://biz-transppayy.com/api/integration/v1`, puis redéployer.

Rien n'a été modifié en prod. Diagnostic 100% basé sur les données lues (DB + secrets metadata + logs).
