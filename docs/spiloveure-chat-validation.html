SPILOVEURE CHAT · 14 NOVEMBRE 2026

Validation de la première version

Un module réel de messagerie a été ajouté à la plateforme existante. Ce rapport distingue les contrôles réalisés des fonctions encore absentes ou dépendantes de l’installation sur le VPS.

Ce n’est pas encore la totalité du cahier des charges Telegram. Les appels audio/vidéo ne sont pas implémentés. Les push hors ligne ne sont pas validés sur un téléphone réel. Aucun chiffrement de bout en bout n’est revendiqué.

Préservation de la plateforme

  • Les comptes existants servent d’identité : aucun nouveau système d’inscription n’est introduit.
  • Le Chat communautaire possède ses propres collections, séparées du support et de sa purge automatique.
  • Le code des paiements, abonnements, marketplace, formations et tâches n’a pas été modifié pour cette intégration.
  • La page Trading reste présente ; seule son entrée dans la barre principale est remplacée par Chat.
  • Aucune modification ni importation de données n’a été effectué sur le VPS de production.

Ces vérifications ne constituent pas une certification exhaustive de tous les parcours historiques ou de tous les prestataires externes.

Limites connues et travail restant

  • Appels audio/vidéo, signalisation WebRTC et relais TURN : non implémentés.
  • Push sur téléphone hors ligne : fournisseur existant réutilisé, mais configuration et réception réelles à vérifier sur le VPS. Les notifications de réactions et mentions ne disposent pas d’un parcours push spécialisé.
  • Pas de chiffrement de bout en bout, antivirus de pièces jointes, ni test de charge à grande échelle.
  • 200 membres maximum par groupe/canal. Fichiers : 20 Mo maximum ; quota de 100 Mo et 100 fichiers par utilisateur sur 24 heures.
  • Les messages en échec sont relançables dans l’écran ouvert ; la boîte d’envoi n’est pas persistante après fermeture de l’onglet.
  • Partage de contacts textuel ; commentaires spécifiques aux canaux, bots, localisation et gestion des appareils non livrés.
  • L’interface suit la référence avec le logo officiel déjà présent dans la plateforme ; aucune certification pixel par pixel n’est annoncée.

Mise à jour du VPS

Après sauvegarde et envoi du code vers le dépôt, reconstruire le backend et le frontend, sans supprimer les volumes ni réimporter la base :

cd /opt/spiloveure
git pull
cd deploy/hostinger
docker compose up -d --build backend web
docker compose logs --tail=80 backend web

Conserver les variables et secrets de production existants. Le site public ne reçoit pas ces changements tant que cette mise à jour n’a pas été exécutée sur le VPS.

Documentation technique incluse dans le projet : docs/spiloveure-chat.md et docs/spv-chat-api.md. Ce rapport porte sur l’environnement local de développement, pas sur une vérification de la production.
